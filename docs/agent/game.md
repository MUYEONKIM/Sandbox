# 게임 구조와 규칙

숫자(좌표, 가격, 크기)는 코드와 DB 표가 기준이다. 이 문서는 어디를 보면 되는지, 무엇을 함께 바꿔야 하는지, 왜 그렇게 정했는지를 적는다.

## 좌표

- 마름모 2:1 격자, 한 칸은 32×16 아트 픽셀, 카메라 2배. 맵은 기본 46×46칸(`src/config.ts`의 `MAP_SIZE`)이고, 건물 층은 바닥 앞쪽에 3칸을 남긴 크기다(`map.ts`의 `mapSize`, 7, 8층은 86×86 맵에 62×80칸 바닥). 칸 번호는 `x + y * map.size`라서 칸을 다루는 코드는 `MAP_SIZE` 대신 `map.size`를 쓴다.
- `+x`는 화면 오른쪽 아래, `+y`는 왼쪽 아래. 위 방향키는 `(-1,-1)`이고, 막히면 벽을 따라 미끄러진다(`GameScene.ts`의 `slideOptions` 함수).
- 앞뒤는 `depthOf(x, y)`로 정한다. 여러 칸짜리 건물은 화면 세로줄 단위로 잘라 줄마다 깊이를 준다(`showBuilding`).
- 맵의 일부만 쓰는 곳(건물 안)은 나머지 칸을 `Terrain.Void`로 채운다. Void는 그리지도, 걷지도 않는다.

## 파일

- `src/game/GameScene.ts`: 화면, 이동, 포탈, 전투, 블록, 작업, 휴대폰 터치. 거의 모든 기능이 여기서 만난다.
- `src/game/maps.ts`: 맵 목록(`MAPS`), 맵 사이 포탈, 평원 건물 위치, 도착 칸(`arrivalFor`), 부활 칸.
- `src/game/tower.ts`: 아이티공간 건물 안의 층, 문, 계단, 엘리베이터, 층 안의 벽(`partitions`)과 뚫린 바닥(`voids`). 시작마을 도박장(`casino`)도 같은 방식의 건물 안이라 여기 `FLOORS`에 있다. 층 그림(바닥, 뒤쪽 벽, 계단 무늬)은 `src/art/interior.ts`가 그리고, 층 안의 벽은 `GameScene.showPartitions`가 칸마다 상자로 세운다.
- `src/game/map.ts`: 맵 하나의 지형, 장애물, 자원 칸. `village.ts`는 시작마을 장식(고정 시드).
- `src/game/world.ts`: 걸을 수 있는지, 블록을 놓을 수 있는지. `path.ts`: 휴대폰 터치 이동의 길 찾기.
- `src/net/session.ts`: 실시간 채널과 서버 호출. `src/net/auth.ts`: 로그인, 프로필, 경제 표 읽기.
- `src/ui/`: DOM 창(상점, 노동청, 카운터 스텟 창 `castle.ts`, 명예의 전당, 엘리베이터 버튼, 도박장 게임 창). 도박장 창은 공통 틀 `bet.ts`(걸 곳, 거는 돈, 결과)와 게임별 그림 `ladder.ts`, `oddeven.ts`, `snail.ts`, 셋을 묶는 `casino.ts`로 나뉜다. 게임 화면은 canvas에 만화풍(굵은 갈색 테두리)으로 그린다.
- `src/game/casino.ts`: 도박장 게임 셋의 이름, 걸 곳, 배당, 거는 돈 범위. 창에 보여 줄 사본이고 결과와 배당은 SQL `place_bet`이 정한다.
- `supabase/migrations/`: 서버 규칙. 같은 함수가 여러 번 고쳐졌으므로 가장 최근 파일이 기준이다.

## 서버가 맡는 것

플레이어가 조작할 수 없도록 체력, 골드, 레벨과 경험치, 스텟, 무기와 도구 소유, 자원, 피해와 회피 판정, 도박 결과는 서버 함수(`hit_player`, `harvest`, `sell_all`, `buy_*`, `respawn`, `place_bet`)가 정한다. 클라이언트가 직접 고칠 수 있는 프로필 열은 `x`, `y`, `map`, `inventory`뿐이다. 체력 변화는 클라이언트가 쓸 수 없는 `world-chat` 채널로 서버가 알린다.

가격, 피해량, 발사 간격, 작업 한 번의 경험치(`workplaces.exp`), 자원 이름과 확률은 DB 표(`weapons`, `stats`, `tools`, `workplaces`, `loot`, `shop_items`)가 기준이라 재배포 없이 바꿀 수 있다. 블록 개수는 클라이언트 인벤토리(`profiles.inventory`)에 있어서 서버가 세지 않는다(친구끼리 노는 게임이라 그대로 둠).

## 함께 바꿔야 하는 곳

- **공격 금지 맵**: `MAPS[id].safe`와 SQL `hit_player`의 맵 목록. 지금은 시작마을(`plains`), 1층 카페(`tower1`), 도박장(`casino`).
- **블록 설치 맵**: `MAPS[id].buildZones`와 `blocks` 표의 insert 정책. 지금은 아이티공간 `tower1`(1층 카페, 바닥 전체 `LOBBY`), `tower4`, `tower7`, `tower8`, `rooftop`과 작업장 `quarry`, `logging`, `gathering`, `fishing`. 서버는 맵 이름만 보고 칸 범위는 클라이언트가 본다(바닥 크기를 바꿔도 SQL이 필요 없게).
- **블록 쌓기 높이**: `config.ts`의 `MAX_STACK`(5)과 `blocks.z` 검사(0~4). `blocks`의 기본 키는 (map, x, y, z)다. 서버는 바로 아래 블록이 있어야 놓게 하고(insert 정책), 맨 위 블록만 빼게 한다(delete 정책). 어떤 블록 위에 쌓을 수 있는지(기본 블록, 곧 상자 위에만)는 클라이언트 `World.canStack`이 본다.
- **좌표 상한**: `profiles`와 `blocks`의 x, y 검사(0~99)와 `config.ts`의 `MAX_MAP_SIZE`(100). 어떤 층을 100칸 넘게 넓히면 둘 다 바꾸고 SQL이 필요하다.
- **레벨에 필요한 경험치**: SQL `level_need`와 `src/game/level.ts`의 `levelNeed`(경험치 막대). 지금은 레벨 × 100.
- **스텟 공식**: SQL(`hit_player`, `harvest`, `buy_stat`)과 `src/game/stats.ts`의 설명. STR, DEF, AGI는 1포인트가 0.1%다(사용자가 "천천히 오래 하는 게임"이라고 정함). LUK는 1포인트에 자원 개수 평균 +0.5%(사용자 요청 2026-11-11), HP는 1포인트에 최대 체력 +1이다(0.1%면 10개를 사야 1이 올라 산 티가 안 남, 에이전트가 정함). 가격은 `stats` 표(지금 20G부터 한 번 살 때마다 +10G, 2026-11-11 사용자 요청으로 1/10).
- **작업 획득량**: SQL `harvest`의 기본 2개와 `src/game/economy.ts`의 `HARVEST_COUNT`(노동청 창의 개수와 분당 벌이). 한 번 캘 때 평균 2 × (1 + LUK × 0.005 + 도구 보너스)개다(사용자 요청 2026-11-11 "작업 획득량 2배").
- **도박장 배당과 거는 돈**: SQL `place_bet`과 `src/game/casino.ts`의 `GAMES`, `BET_MIN`(10G), `BET_MAX`(100,000G).
- **최대 체력**: SQL `profiles.max_hp`(기본 100, 산 HP 포인트는 `max_hp - 100`)와 `src/config.ts`의 `BASE_HP`. 다른 사람의 체력 막대 비율은 이동 알림의 `maxHp`와 서버 체력 알림의 `max`로 안다.
- **태어나는 곳**: 서버 `profiles` 표의 기본값(`map` `tower7`, `x` 23, `y` 23)만 정한다. 바꾸려면 SQL로 기본값을 바꾸고 그 칸이 걸을 수 있는 칸인지 본다. 저장된 맵 이름을 모르면 클라이언트는 시작마을에서 시작한다(`auth.ts`의 `loadProfile`).
- **블록 종류**: `src/blocks.ts`의 `BLOCKS`(이름, 지나갈 수 있는지, 그림 종류 cube/sprite/tile). cube(기본 블록)는 `public/sprites/block-textures.png`(16×16 텍스처를 가로로 이은 것)의 `texture`번째 칸으로 `src/art/cube.ts`가 상자를 그린다(`side`가 있으면 옆면은 그 칸, 투명한 텍스처 칸은 옅은 유리색). 새 상자 블록은 텍스처를 그 그림 오른쪽에 붙이고(`art-source/textures/make-sheet.cjs`의 `PICKS`에 원본 위치 추가) 한 줄을 더한다. 상점에서 팔려면 DB `shop_items`에 같은 id로 가격과 묶음 수를 넣는다. 상점 창은 cube를 "기본 블록", 나머지를 "꾸미기" 칸에 나눠 보여 준다.
- **처음 주는 블록**: 가입할 때 `inventory.ts`의 `STARTER_BLOCKS`(벽 4종)를 단축키 칸과 가방에 한 묶음씩 준다. 그 뒤에 더한 기본 블록 11종은 `BASIC_GIFT`로 계정마다 한 번 한 묶음씩 준다(접속할 때 `main.ts`가 SQL `claim_gift`를 불러 처음일 때만 가방에 넣음). 서버 `gifts` 표가 두 번 받지 않게 막고, `claim_gift`는 아는 선물 이름만 받는다. 새 선물을 만들면 이름을 SQL 목록에 더한다.
- **새 맵**: `MapId`, `MAPS`, 포탈 양쪽. 건물 안 맵은 `MAPS`의 `links`가 아니라 `tower.ts`의 `FLOORS`에서 포탈을 받는다. 포탈이 하나도 없으면 부활 칸(`respawnTile`)이 없어 깨진다.
  - 실시간 채널은 `world:<맵>`이고 정책이 `world:%`를 허용하므로 채널 때문에 SQL이 필요하지는 않다.
  - 새 맵은 기본으로 공격이 되고 블록은 안 된다. 공격을 막거나 블록을 허용하려면 위의 두 항목처럼 SQL도 바꾼다.

## 장소

- **시작마을(`plains`)**: 가운데 유리 타워 `아이티공간`(정문으로 건물 1층에 들어감), 오른쪽 위 `상점`(무기, 도구 구매와 자원 판매), 위쪽 귀퉁이 `노동청`(작업장 선택), 성문 앞 `명예의 전당` 게시판, 오른쪽 맵 끝 주점 건물의 `인생한방 도박장`(오른쪽 벽에 그려진 문 (45, 14), `maps.ts`의 `CASINO_DOOR`). 오른쪽 귀퉁이는 사막, 왼쪽은 숲. 돌길은 마을 안 길, 흙길은 다른 맵으로 나가는 길이다.
- **인생한방 도박장(`casino`)**: 사용자 요청 2026-11-11 "시작마을 아무 건물에 포탈 열어서 도박장". 18×18칸 붉은 카펫 방(`CASINO_HALL`)이고 공격과 블록이 막혀 있다. 오른쪽 벽에 사다리판과 홀짝판, 왼쪽 벽을 따라 달팽이 경주로(`SNAIL_TRACK`, 지나갈 수 없음)가 있고, 각 판 앞 포탈을 밟으면 그 게임 창이 열린다. 한 판은 혼자 바로 하는 방식이다(다른 사람과 같은 판을 함께 보는 회차 방식이 아님).
  - 사다리: 출발(좌, 우)과 가로줄 수(3, 4)가 무작위다. 하나만 맞히면 1.96배, 둘 다 맞히면 3.97배. 도착(홀, 짝)은 그림에만 보이고 걸 수 없다(좌3·우4는 짝, 좌4·우3은 홀).
  - 홀짝: 구슬 1~10개가 무작위, 1.96배.
  - 달팽이 경주: 1, 2, 3번 중 1등이 무작위, 2.97배. 중간 순위와 2, 3등은 창이 꾸며 보여 줄 뿐이다. 배경(`public/casino/snail-race.webp`, 흙길 세 줄과 "달팽이 레이싱 게임" 간판)과 달팽이 실루엣(`public/casino/snail.svg`, 왼쪽을 봄)은 사용자가 줬다(2026-11-11). 실루엣에 껍데기 번호 색, 크림색 몸, 테두리, 소용돌이, 눈을 창이 칠하고 뒤집어 오른쪽으로 달린다. 흙길 높이와 출발, 결승 위치는 `snail.ts`의 `LANE_Y`, `START_X`, `FINISH_X`(배경 비율)라 배경을 바꾸면 함께 맞춘다.
  - 홀짝 화면: 붉은 커튼, 사슬에 매달린 "홀짝 게임" 간판, 둥근 펠트 탁자, 왼쪽 홀(빨강)과 오른쪽 짝(파랑) 자리, 놋그릇과 유리구슬. 사용자가 처음 그림을 "너무 구리다"고 해서 다시 그렸다(2026-11-11).
  - 건 돈은 바로 빠진 것처럼 보이고, 연출이 끝나면 받은 돈(건 돈 포함)이 들어온다. 배당은 사용자가 정했고, 거는 돈 범위(10G~100,000G)는 에이전트가 정했다. 서버는 도박장 맵에 있을 때만 받고 판마다 `bets` 표에 남긴다(클라이언트는 못 읽음).
- **다른 맵**: 사막 → 화산, 숲 → 설원. 작업장 4곳(채석장, 벌목장, 채집장, 낚시터)은 노동청에서 간다. 작업장은 블록과 공격(PK)이 되는 곳이고, 도착 귀퉁이 근처에 장식 벽이 한두 줄 있다(`map.ts`의 `WORK_WALLS`). 장식 벽은 돌벽 상자 그림을 쓰지만 맵에 박혀 있어 회수할 수 없다.
- **아이티공간 건물**: 9층과 옥상이 있지만 1, 4, 7, 8층과 옥상만 들어간다.
  - 1층: 카페 ITS'room. 카운터 앞에서 스텟을 산다. 공격 금지지만 블록은 바닥 어디에나 놓는다(사용자 요청 2026-11-10).
  - 엘리베이터: 포탈을 타면 엘리베이터 안(`elevator` 맵)에 들어간다. 안의 포탈은 층 버튼판 하나뿐이다(사용자가 나가는 문을 따로 두지 말라고 함). 버튼판 창에서 1, 4, 7층을 고르거나 "○층에서 내리기"로 탔던 층에 나간다(새로고침하면 1층). 2, 3, 5, 6층은 "임대 줬습니다"로 막는다. 모든 층이 한 엘리베이터를 같이 쓴다.
  - 7, 8층은 사용자가 준 실제 평면도(2026-11-11, 원본과 도구는 `art-source/floorplans/`)대로 벽을 세웠다. 평면도 한 칸 = 7.16pt로 옮겨 62×80칸이다(`TOP_FLOORS`). 엘리베이터가 화면 아래(앞쪽)에 오게 놓아서(사용자 요청 2026-11-11), 평면도 아래 변(계단실, 엘리베이터, 아래쪽 방)과 왼쪽 창가(방 세 개)가 앞쪽 두 변이고, 뒤쪽 왼쪽 벽이 평면도 위 변, 뒤쪽 오른쪽 벽이 평면도 오른쪽 변이다. 넓은 사무실은 뒤쪽에 있다. `tower.ts`의 `at(gx, gy)`가 평면도 좌표(gx: 아래에서 위, gy: 왼쪽에서 오른쪽)를 맵 칸으로 돌려 바꾸므로, 벽과 포탈은 평면도 좌표로 적는다. 계단 오르는 쪽도 평면도 기준으로 적고 `flight()`가 뒤집는다.
  - 문은 벽을 비운 3칸이고, 평면도의 문 호 자리에 뚫었다. 평면도의 창가 돌출부, 바깥 기둥, 화장실 칸막이, 복도의 작은 벽 조각은 뺐다.
  - 벽 종류: 방을 나누는 흰 벽(`wall`)과 8층 뚫린 바닥 둘레 유리 난간(`glass`)은 칸 가운데를 지나는 얇은 판(`src/art/partition.ts`)이고 이웃 벽 쪽으로 팔을 뻗어 이어진다(사용자가 블록 같은 두꺼운 벽이 벽 같지 않다고 함, 2026-11-11). 엘리베이터 통과 덕트, 기둥은 매끈한 콘크리트 덩어리(`core`)다. 얇은 벽은 콘크리트나 뒤쪽 벽과는 벽이 그쪽으로 이어질 때만 붙인다(나란히 지날 때까지 붙이면 칸마다 팔이 튀어나와 톱니처럼 보임). 모두 칸을 막고 점프로 못 넘으며(`World.blocksJump`), 내 캐릭터를 가리면 반투명해진다. 미니맵에도 벽으로 보인다.
  - 7층: 엘리베이터 문은 계단실 쪽 앞면, 계단실 문 옆 짧은 벽 바로 옆이다. 가운데 홀에서 계단 앞 공간으로 바로 들어가는 문이 있고, 계단실 옆 덕트는 없다(사용자가 실제 화면에 그려 고침, 2026-11-11). 가운데 U자 계단은 계단 앞 공간에서 아래 계단, 층참, 위 계단을 걸어 올라 끝 칸(포탈)에서 8층으로 간다. 계단 앞 공간에서 위 계단 끝으로 바로 가지 못하게 난간을 뒀다. 계단실(평면도 아래 왼쪽)은 계단 무늬만 있고 어디로도 가지 않는다.
  - 8층: 엘리베이터가 서지 않아 엘리베이터 통에 문이 없다. 가운데 계단 끝 칸을 밟으면 7층 계단 앞 공간으로 내려간다. 7층 가운데 홀 위가 뚫려 있어(평면도의 X 표시) 걸을 수 없고 어둡게 그린다. 옥상으로 가는 바깥 계단 맵(`stairs`) 문은 뒤쪽 오른쪽 벽(평면도 오른쪽 변 가운데쯤, `ROOF_EXIT`)에 그린 비상구다. 사용자가 실제 화면에 자리를 표시했다(2026-11-11). 계단실은 계단 무늬만 있는 방이다.
  - 4층과 옥상: 40×40칸(`UPPER`). 7, 8층과 함께 블록과 무기를 쓰는 자유 공간이다. 1층은 20×20.
  - 층 구조를 바꾸면 그 자리에 있던 옛 블록은 서버에 남지만 벽 칸이나 바닥 밖이면 그리지 않는다(`onBlockPlaced`). 저장된 자리가 벽이면 첫 포탈 앞에서 시작한다.
  - 4층 숨은 방(`tower.ts`의 `HIDEOUT`): 바닥 오른쪽 아래 끝 칸 (42, 15)를 밟으면 "진우씨가 유일하게 맘 편히 쉬었던 안식처"가 크게 뜨고, 바닥 밖 3×7칸(x 43~45, y 12~18)에 이불, 스탠드, 밥상, 화분이 있는 방이 서서히 나타나 걸어 들어갈 수 있다. 자리와 문구는 사용자가 정했다(실제 사이트 test 계정이 서 있던 칸). 밟은 사람 화면에서만, 여는 칸이나 방 안을 밟고 있는 동안에만 보이고(사용자 요청 2026-11-09) 벗어나면 0.5초 동안 사라지며 다시 허공이 된다. 다시 밟을 때마다 문구가 뜬다. 서버는 모르는 방이라 SQL이 없고, 그 안에서 접속을 끊으면 방이 열린 채로 시작한다. 여는 칸에는 블록을 놓을 수 없다(`GameMap.reserved`).
  - 계단은 높이 없이 바닥에 계단 무늬로 그렸다. 진짜 높이를 넣으려면 캐릭터, 총알, 블록의 높이 처리가 함께 바뀐다.

## 이동과 조작

- 방향키 또는 WASD는 화면 방향 기준이고, 두 키를 함께 누르면 마름모 변을 따라 간다. Shift는 누르는 동안 달리기, Space는 점프(블록 하나를 넘음, 두 개 이상 쌓인 칸은 못 넘음), F는 작업, I는 인벤토리, Enter는 채팅.
- 포탈로 맵을 옮기면 누르고 있던 방향키를 잊는다. 계단 포탈에 도착하자마자 되돌아가는 일을 막으려는 것이다.
- 휴대폰: 바닥을 누르면 그 칸까지 길을 찾아 걷는다. 무기를 들고 다른 플레이어를 누르면 공격한다. 블록, 점프, 달리기, 작업, 인벤토리, 채팅은 아직 휴대폰에서 할 수 없다.

## 전투와 성장

- 레벨은 경험치로 오른다. 한 번 캘 때 얻는 경험치는 레벨과 상관없이 작업장마다 같고(작업 1초에 1000: 채집장 1500, 채석장 2500, 벌목장 3000, 낚시터 5000), 다음 레벨에 필요한 경험치가 레벨 × 100으로 늘어 처음에는 빨리 오른다(방향은 사용자가, 숫자는 에이전트가 정함). 상대를 쓰러뜨리면 경험치 10000. 2026-11-11에 사용자가 "너무 적게 들어온다"며 모두 100배로 올렸다. 레벨은 표기만 늘고 능력치와는 무관하다. 계산은 SQL `gain_exp`가 하고, 한 번에 여러 레벨이 오를 수 있다.
- 예전에는 캘 때마다 현재 레벨에 비례해 폭발적으로 올랐다. 바꾸면서 모든 플레이어를 Lv.1로 되돌렸다(2026-11-08 사용자 결정).
- 체력은 기본 100이고 HP 스텟 1포인트마다 최대 체력이 1 늘어난다. 쓰러지면 3초 뒤 그 맵의 첫 포탈 앞(시작마을은 성 정문 앞)에서 다시 시작한다. 사거리는 클라이언트가, 같은 맵인지는 서버가 본다(친구끼리 노는 게임이라 그대로 둠).
- 상점(시작마을)은 무기, 꾸미기 블록, 작업 도구를 팔고 자원을 사 준다. 꾸미기 블록은 한 칸짜리(벽 4종, 참나무, 소나무, 전나무, 꽃, 풀, 바위, 통나무, 작은 덤불, 카페 테이블, 화분)만 판다. 사용자가 여러 칸짜리 건물은 빼기로 했다. 꽃과 풀은 밟고 지나가고 총알도 지나간다.
- 블록 쌓기(사용자 요청 2026-11-09): 블록을 들고 기본 블록(상자)을 가리키면 그 위에 쌓일 자리가 반투명하게 보이고, 좌클릭으로 한 칸에 다섯 개까지 쌓는다. 기본 블록 위에는 아무 블록이나 올릴 수 있고(벽 위 화분, 꽃), 나무나 화분 같은 꾸미기 블록 위에는 못 쌓는다. 우클릭은 맨 위 블록부터 회수한다. 지나갈 수 있는지와 총알은 바닥 블록만 본다. 맵에 박힌 장식 벽 위에는 못 쌓는다(서버가 아래 블록을 확인하기 때문).
- 벽 블록 그림(사용자 요청 2026-11-10): 예전에는 받은 성벽 조각 그림 한 장에 색만 입혀 이웃끼리 잇는 담장이었는데, 사용자가 준 16px 텍스처로 그린 상자로 바꿨다(돌벽은 회색 돌 벽돌, 벽돌벽은 빨간 벽돌, 나무벽은 나무판, 덤불벽은 나뭇잎). 이웃과 잇지 않고 상자끼리 붙는다. 상자는 내 캐릭터의 몸이나 머리를 가리면 나무처럼 반투명해진다(`covers.ts`).
- 기본 블록 11종 추가(사용자 요청 2026-11-10 "상점이랑 인벤토리에 기본블록들을 여러 개 더"): 조약돌, 흙, 잔디(윗면 풀, 옆면 흙), 모래, 유리(속이 비침), 눈 블록, 흰·검은·빨간·파란·노란 블록. 상점에서 16개 120G(벽과 같음)이고, 모든 플레이어가 한 번 한 묶음(64개)씩 받는다. 가방 자리가 모자라면 남는 것은 받지 못한다.
- 스텟 STR, DEF, AGI, LUK, HP는 카운터에서 골드로 산다. HP를 사면 지금 체력도 1 찬다(쓰러져 있으면 그대로). LUK는 자원 개수만 늘린다. 작업 도구는 해당 작업장 획득량을 평균 50% 늘린다. 한 번 캘 때 기본 2개다.
- 작업(F) 동작은 `workFx.ts`가 그리고 내 화면에만 보인다. 조각은 바닥색과 대비되는 색이어야 보인다.
- 명예의 전당 창은 열 때마다 `top_players`로 상위 50명을 읽고, 미니맵 밑 TOP 10은 접속할 때와 매시 정각에 읽는다(사용자가 1시간으로 정함).
- 가입 때 고르는 캐릭터는 `profiles.skin`(0~6). 고르기 전에 가입한 옛 계정은 null이고 id로 정해진다.

## 그림

- 7, 8층 벽 그림도 같은 텍스처 묶음에서 골랐다(`block-textures.png` 16번 콘크리트. 얇은 벽과 유리 난간은 텍스처 없이 색으로 그린다). 평면도는 `art-source/floorplans/`의 `pdfpage.cjs`(.ai에서 선 꺼내기), `pdfdraw.cjs`(그림), `planlines.cjs`(칸 좌표로 선 목록), `verify-plan.mjs`(게임 벽을 평면도 위에 겹쳐 그리기)로 옮겼다.
- 블록 텍스처 원본은 사용자가 준 16px 이음매 없는 무늬 묶음이다(`art-source/textures/`, 같은 그림이 여러 형태로 들어 있음). 쓰는 것만 `make-sheet.cjs`로 골라 `block-textures.png`로 만든다. 출처와 사용 조건은 아직 사용자에게 듣지 못했다.
- 캐릭터 `team.png`(7명, 2프레임)에는 뒷모습이 없어 `team-back.png`를 앞모습에서 만들었다. 진짜 뒷모습을 받으면 같은 배치로 이 파일만 바꾼다.
- 중세 마을 건물과 캐릭터, 타일은 사용자가 준 에셋이고 라이선스 파일이 없다(사용자가 알고 배포를 정함).
- 유리 타워(`castle.png`, 사용자가 후보 중 고름, 다른 후보는 `art-source/castle-candidates/`), 게시판(`board.png`), 카페 가구(`counter`, `cafe-table`, `plant`)는 내가 그렸다. 사용자는 중세풍 성이 너무 앤티크하다고 했다.
- 캐릭터를 가리는 건물과 나무는 `covers.ts`가 반투명하게 만든다. 나무 배치(시드)가 바뀌면 건물 앞을 가리는지 다시 본다(`firtree.png`는 여러 그루라 품이 넓다).
