# 게임 구조와 규칙

숫자(좌표, 가격, 크기)는 코드와 DB 표가 기준이다. 이 문서는 어디를 보면 되는지, 무엇을 함께 바꿔야 하는지, 왜 그렇게 정했는지를 적는다.

## 좌표

- 마름모 2:1 격자, 한 칸은 32×16 아트 픽셀, 카메라 2배. 맵은 기본 46×46칸(`src/config.ts`의 `MAP_SIZE`)이고, 건물 층은 바닥 앞쪽에 3칸을 남긴 크기다(`map.ts`의 `mapSize`, 7, 8층은 86×86 맵에 62×80칸 바닥). 칸 번호는 `x + y * map.size`라서 칸을 다루는 코드는 `MAP_SIZE` 대신 `map.size`를 쓴다.
- `+x`는 화면 오른쪽 아래, `+y`는 왼쪽 아래. 위 방향키는 `(-1,-1)`이고, 막히면 벽을 따라 미끄러진다(`GameScene.ts`의 `slideOptions` 함수).
- 앞뒤는 `depthOf(x, y)`로 정한다. 여러 칸짜리 건물은 화면 세로줄 단위로 잘라 줄마다 깊이를 준다(`showBuilding`).
- 맵의 일부만 쓰는 곳(건물 안)은 나머지 칸을 `Terrain.Void`로 채운다. Void는 그리지도, 걷지도 않는다.

## 파일

- `src/game/GameScene.ts`: 화면, 이동, 포탈, 전투, 블록, 작업, 휴대폰 터치. 거의 모든 기능이 여기서 만난다.
- `src/game/maps.ts`: 맵 목록(`MAPS`), 맵 사이 포탈, 평원 건물 위치, 도착 칸(`arrivalFor`), 부활 칸.
- `src/game/tower.ts`: 아이티공간 건물 안의 층, 문, 계단, 엘리베이터, 층 안의 벽(`partitions`)과 뚫린 바닥(`voids`). 시작마을 도박장(`casino`)과 증권거래소 안(`exchange`)도 같은 방식의 건물 안이라 여기 `FLOORS`에 있다. 층 그림(바닥, 뒤쪽 벽, 계단 무늬)은 `src/art/interior.ts`가 그리고, 층 안의 벽은 `GameScene.showPartitions`가 칸마다 상자로 세운다.
- `src/game/map.ts`: 맵 하나의 지형, 장애물, 자원 칸. `village.ts`는 시작마을 장식(고정 시드).
- `src/game/world.ts`: 걸을 수 있는지, 블록을 놓을 수 있는지. `path.ts`: 휴대폰 터치 이동의 길 찾기.
- `src/net/session.ts`: 실시간 채널과 서버 호출. `src/net/auth.ts`: 로그인, 프로필, 경제 표 읽기.
  - 맵마다 `world:<맵>` 채널에 들고, 접속 명단(presence)에 각자의 위치, 닉네임, 체력, 레벨, 작업 칸을 싣는다. 맵에 들어오면 명단만으로 다른 사람을 바로 그린다(사용자가 "들어오고 조금 있어야 상대가 보인다"고 함, 2026-11-11). 명단은 위치나 체력, 레벨이 바뀌면 고치되 15초에 한 번까지만 고친다(`PRESENCE_GAP_MS`). Supabase는 한 사람이 30초에 명단을 5번(채널에 들 때 포함)까지만 고치게 하고, 넘으면 채널을 닫는다(ClientPresenceRateLimitReached). 처음에 멈출 때마다 고쳤다가 이 제한에 걸려 "연결하는 중 (채널이 닫힘)"이 계속 떴다(2026-11-11). 명단을 더 자주 고치는 기능을 넣지 않는다. 걷는 동안의 위치는 이동 알림(`move`)이 맡는다. 새 사람이 들어오면 기존 사람들이 지금 위치를 한 번 더 보낸다.
  - 실시간 연결의 유지 신호는 워커에서 보낸다(`supabase.ts`의 `realtime.worker`). 숨은 탭에서도 연결이 끊기지 않게 하려는 것이다.
  - 맵 채널이 끊기면 "서버에 연결하는 중입니다" 옆에 이유(채널 오류, 서버 응답 없음, 채널이 닫힘과 서버가 준 설명, 닫힘이면 서버의 마지막 시스템 메시지)를 띄우고 콘솔에도 `[실시간 연결 끊김]`으로 남긴다. 3초 뒤에도 안 돌아오면 채널을 치우고 새로 만들어 다시 들고, 실패하면 간격을 두 배씩(최대 30초) 늘린다. 라이브러리는 같은 이름의 채널을 만들면 남아 있던 것을 돌려주므로, 채널을 들기 전에 같은 이름의 남은 채널을 먼저 치운다(`dropTopic`). 사용자가 2026-11-11에 문구가 계속 뜬다고 했지만 앱 브라우저 창에서는 재현하지 못해 이 장치를 넣었다. 다음에 문구가 뜨면 괄호 속 이유로 원인을 찾는다.
- `src/ui/`: DOM 창(상점, 노동청, 카운터 스텟 창 `castle.ts`, 명예의 전당, 게시판 `board.ts`, 새 버전 안내 `newVersion.ts`, 현상범 명단 `wanted.ts`, 증권거래소 `exchange.ts`, I 창의 정보창 탭 `info.ts`, 엘리베이터 버튼, 도박장 게임 창). 화면 가운데 작은 창(새 소식 `whatsNew.ts`, 메모와 골드 버리기 `ground.ts`, 닉네임 바꾸기 `rename.ts`)은 공통 틀 `modal.ts`를 쓴다. 이 창이 열려 있으면 `anyModalOpen()`으로 `GameScene.canAct`와 채팅, Esc가 막히거나 이 창부터 닫는다. 도박장 창은 공통 틀 `bet.ts`(걸 곳, 거는 돈, 결과)와 게임별 그림 `ladder.ts`, `oddeven.ts`, `snail.ts`, 셋을 묶는 `casino.ts`로 나뉜다. 게임 화면은 canvas에 그린다. 홀짝·사다리는 2026-11-16부터 도트 그림(배경 한 장 + `pixelArt.ts` 조각), 달팽이 경주는 사용자가 준 배경 그림이다.
- 화면 UI 스킨(사용자가 2026-11-13에 준 새 UI 팩, 같은 날 Sprout Lands 팩에서 바꿈 "UI를 다른 걸로 변경, 이전 UI assets는 삭제해도 된다"): `src/style.css`의 'UI 스킨' 블록. 팩 원본은 저장소 맨 위 `NEWUI/`와 복사본 `art-source/newui/`(둘 다 커밋 안 함), 쓰는 조각은 `node art-source/newui/make-skin.cjs`가 `src/ui/skin/`에 자른다(창 `panel.png`, 아래 막대 `panel-dark.png`, 버튼 `button.png`·`button-down.png`(누름)·`button-light.png`(주 버튼)·`button-light-down.png`(고른 탭, 엘리베이터가 선 층)). 팩의 버튼은 초록인데 사용자가 "갈색 느낌, 글자는 밝게"를 요청해(2026-11-13) 스크립트가 같은 모양에 갈색을 입힌다(`BROWN`, `BROWN_LIGHT` 색 바꾸기 표). 조각 자리는 같은 폴더의 `bbox.cjs`(조각 테두리 상자와 색 찍기), `zoom.cjs`(확대해 보기)로 찾는다. `border-image`로 조각을 9칸으로 나눠 2배로 늘려 입힌다. 칸은 팩에서도 무늬 없는 황토색 네모라 그림 없이 색으로 그리고, 팩에 마우스 커서가 없어 기본 커서를 쓴다. 색은 `:root` 변수(바탕 #e5d6a1, 테두리 #603928, 글자와 강조 글자 #3e1f1d(사용자가 미니맵 제목 색을 보내며 "이 정도 색"), 버튼 글자 #fbf3dc). 어두운 바탕을 쓰는 것(게임 화면 위에 바로 뜨는 이름표, 채팅, 줍기 안내, 위쪽 알림과 갈색 아래 막대)은 그 안에서 변수를 밝은 글자 값으로 되돌린다. 어느 조각을 어디에 쓸지와 색은 에이전트가 정했다. 팩 폴더에 라이선스 파일이 없다. src 안의 그림과 글꼴은 Vite가 해시를 붙이거나 CSS에 넣어 배포 직후 옛 파일이 남지 않는다.
- 왼쪽 위 조작 안내(`hud.ts`의 `HELP_ROWS`): 항목마다 한 줄에 이름과 키 단추(`kbd`)로 나눴다(사용자 2026-11-13 "글자만 이어져 있어 가독성이 떨어진다"). H로 여닫는다(사용자 요청 2026-11-13, `Hud.toggleHelp`, `keys.ts`의 `onHelp`). 닫으면 "조작 안내 [H]" 작은 상자만 남고 누르면 다시 열리며, 닫은 상태는 브라우저 `localStorage`의 `help-closed`에 남는다(작은 상자와 저장은 에이전트가 정함). 휴대폰(터치)과 폭 620px 이하에서는 키보드가 없고 다른 상자를 가려서 숨긴다(에이전트가 정함).
- 늘 떠 있는 창 접기(2026-11-16 사용자 "기본으로 화면에 뜨는 여러 팝업창들 최소화 버튼", 설계 디자인 세션 공유 노트 `ui-minimize.md`, 2026-11-16 넷째 배포): 조작 안내, 현상범, 미니맵, 레벨 TOP 10, 채팅 다섯 창의 오른쪽 위에 −/+ 버튼(`src/ui/fold.ts`의 `foldButton`, 게임 버튼 그림에 2px 막대, 24px·휴대폰 30px). 계정 줄과 아래 막대는 접지 않는다(사용자가 정함). 접으면 제목 줄만 남는다(미니맵은 맵 이름, 현상범은 "현상범 N명", 채팅은 "채팅 [새 메시지 수] +"로 접혀 있는 동안 받은 남의 채팅만 셈, 99를 넘으면 99+). + 버튼이나 접힌 제목 줄을 누르면 편다. 조작 안내는 버튼이 `toggleHelp`(H와 같음)를 불러 예전 `help-closed`를 그대로 쓴다. 나머지 넷은 `localStorage`의 `ui-folded`(접은 창 이름 목록, 계정 구분 없음)에 남고, 아직 없으면서 폭 620px 이하면 레벨 TOP 10과 현상범을 접은 채로 시작한다(사용자가 정함). 버튼은 `pointerdown`에서 `preventDefault`하고 `tabIndex = -1`이라 초점을 가져가지 않는다(남아 있으면 Space·Enter가 버튼을 다시 누름). 휴대폰 폭에서는 왼쪽 위 칸을 계정 줄 아래(`top: 94px`)로 내린다(사용자가 정함). 접힌 채로 Enter를 치면 입력 줄만 뜬다. 현상범 명단(60초마다)과 레벨 순위(매시 정각) 읽기는 접혀도 한다(이름 색이 명단에서 옴). 미니맵은 접혀 있으면 `GameScene.updateMinimap`이 첫 줄에서 돌아가고, 펼쳐 있어도 0.1초마다 맵, 블록(`World.version`), 숨은 방, 내 칸, 다른 사람 칸이 바뀌었는지만 보고 바뀌었을 때만 블록 목록을 만들어 그린다(예전에는 1초에 10번 늘 그림. 블록 1,252개 벌목장에서 서 있으면 0번, 걸으면 칸이 바뀔 때마다 약 7번, 접으면 0번, 한 번 그리기 약 0.4ms, 2026-11-16 로컬). 펴는 순간 한 번 그린다.

- `src/ui/landMap.ts`와 `landMap.css`: 농협 땅 지도(마름모 농장, 2026-11-16). 스타일은 `style.css`가 아니라 이 파일에 있다(디자인 세션 파일을 건드리지 않으려고, 에이전트가 정함).
- `src/game/casino.ts`: 도박장 게임 셋의 이름, 걸 곳, 배당, 거는 돈 범위. 창에 보여 줄 사본이고 결과와 배당은 SQL `place_bet`이 정한다.
- `supabase/migrations/`: 서버 규칙. 같은 함수가 여러 번 고쳐졌으므로 가장 최근 파일이 기준이다.

## 서버가 맡는 것

플레이어가 조작할 수 없도록 체력, 골드, 레벨과 경험치, 스텟, 무기와 도구 소유, 자원, 피해와 회피 판정, 도박 결과, 악업과 현상금은 서버 함수(`hit_player`, `harvest`, `sell_all`, `buy_*`, `respawn`, `place_bet`)가 정한다. 게시판 글도 `board_posts` 표에 직접 손대지 못하고 `write_post`, `read_board`, `delete_post`로만 쓴다. 주식 가격(`stocks`), 보유 주식(`holdings`), 거래 기록(`trades`)도 클라이언트가 직접 못 읽고 `stock_quotes`, `my_holdings`, `trade_stock`으로만 다룬다. 클라이언트가 직접 고칠 수 있는 프로필 열은 `x`, `y`, `map`, `inventory`뿐이다. 체력 변화는 클라이언트가 쓸 수 없는 `world-chat` 채널로 서버가 알린다.

가격, 피해량, 발사 간격, 탄창·재장전·알 수, 작업 한 번의 경험치(`workplaces.exp`), 자원 이름과 확률, 강화 확률과 판매가(`forge_steps`)는 DB 표(`weapons`, `stats`, `tools`, `workplaces`, `loot`, `forge_steps`)가 기준이라 재배포 없이 바꿀 수 있다. 무기 소유와 강화 단계는 `gear` 표(한 줄이 한 자루, 내 줄만 읽힘)이고 `buy_gear`, `sell_gear`, `forge_gear`로만 바뀐다. 블록과 꾸미기는 누구나 모든 종류를 무제한으로 가져서(사용자 요청 2026-11-11) 서버가 개수를 세지 않는다. `profiles.inventory`에는 칸 배치만 저장된다. 상점 블록 표 `shop_items`와 `buy_item`, 선물 표 `gifts`와 `claim_gift`는 DB에 남아 있지만 쓰지 않는다.

## 함께 바꿔야 하는 곳

- **공격 금지 맵**: `MAPS[id].safe`와 SQL `hit_player`의 맵 목록. 시작마을(`plains`)과 그 안의 상점 안(`mart`), 대장간 안(`smithy`), 노동청 안(`labor`), 농협 안(`farmcoop`)이다(안 맵들은 에이전트가 정함, 뒤의 둘은 SQL `20261116010000_interior_rooms.sql`)(사용자 요청 2026-11-11 "공격은 시작마을에서만 제외"). 1층 카페와 도박장도 공격이 된다. 모험 맵 아홉 장(`adv_gate`, `adv_1`~`adv_8`, id가 `adv_`로 시작)도 막는다(SQL `20261117000000_adventure.sql`, 아직 로컬에만).
- **블록 설치**: 모든 맵의 바닥 전체에 놓는다(사용자 요청 2026-11-11 "모든 구역에서 가능"). `map.ts`가 바닥(건물 안은 층 바닥, 나머지는 맵 전체)을 설치 구역으로 주고, 벽, 물, 건물, 포탈 둘레처럼 놓을 수 없는 칸은 `World.canPlace`가 거른다. 서버 `blocks` insert 정책은 맵을 보지 않고 쌓기 조건만 본다.
- **블록 쌓기 높이**: `config.ts`의 `MAX_STACK`(5)과 `blocks.z` 검사(0~4). `blocks`의 기본 키는 (map, x, y, z)다. 서버는 바로 아래 블록이 있어야 놓게 하고(insert 정책), 맨 위 블록만 빼게 한다(delete 정책). 어떤 블록 위에 쌓을 수 있는지(기본 블록, 곧 상자 위에만)는 클라이언트 `World.canStack`이 본다.
- **좌표 상한**: `profiles`와 `blocks`의 x, y 검사(0~99)와 `config.ts`의 `MAX_MAP_SIZE`(100). 어떤 층을 100칸 넘게 넓히면 둘 다 바꾸고 SQL이 필요하다.
- **골드 형식**(2026-11-15, 대장간 판매가가 10^42까지 가서 상한을 없앰, 사용자가 정함): SQL `profiles.gold`는 `numeric(1000, 0)`(소수점 아래 없음, 에이전트가 정함)이고, 골드를 돌려주는 함수는 골드를 글자로 보낸다(`sell_all`, `buy_tool`, `buy_weapon`은 글자 하나, 나머지는 jsonb의 `gold` 칸이 글자). 클라이언트는 `auth.ts`에서 `gold::text`로 읽고 `session.ts`에서 BigInt로 바꾼다. 새 함수가 골드를 바꾸면 같은 규칙을 지킨다: 계산은 numeric, 돌려줄 때 `::text`, 화면은 `toGold`와 `goldText`. 함께 쓰는 칸 가운데 `bets.amount`(한 판 10만G), `ground_items.amount`(한 번 약 21억, 화면 `ground.ts`의 `DROP_MAX`), `holdings.cost`(bigint)는 한 번에 넣는 양이 묶여 있어 그대로 뒀다(에이전트가 정함). 스텟과 체력 칸(`str`, `def`, `agi`, `luk`, `max_hp`, `hp`)은 bigint이고 2^53 − 1에서 멈춘다(화면이 Number로 정확히 세는 끝, 에이전트가 정함). `buy_stat`은 한 번에 1~10억 포인트를 받고(카운터 창 `castle.ts`의 `AMOUNT_MAX`, 직접 입력 칸), 값은 서버와 `economy.statPrice` 모두 큰 수로 셈한다. 남는 한계: 작업 한 번의 개수와 `stash.count`는 integer라 LUK가 약 2,100억을 넘으면 작업이 거절된다(골드 약 10^24가 필요해 그대로 둠).
- **무기 종류와 수치**(2026-11-16 대장간 배포, `docs/balance/weapons.md` 6장): SQL `weapons` 표(값, 피해, 발사 간격, `magazine` 탄창, `reload_ms` 재장전, `pellets` 알 수)와 `src/items.ts`의 `WEAPONS`(이름, 사거리, 근접 무기의 베는 폭 `arc`(도), 흩어짐, 산탄 부채꼴 `fan`, 손에 든 그림과 아이콘). 새 종류는 둘 다 더하고 그림(`forgeArt.ts`의 칸)을 짝짓는다. 검의 id는 예전 그대로 `sword`이고 이름만 장검이다(옮기는 칸을 줄이려고, 에이전트가 정함).
- **대장간 값**: SQL `forge_steps`(단계마다 성공·유지·하락·파괴 백만분율과 판매가), `gear_price`(판매가 = div(무기값 × (300 × p + LUK × greatest(p − 1000, 0)), 300000), p = 표 값. 무기값을 넘는 몫(+8부터)에만 LUK 배율이 붙는다), `buy_gear`(사는 값 = 무기값, LUK와 상관없음), `forge_gear`(강화비 판매가 1% 반올림, 두루마리 값 올림, 망치질 간격 3초 × 무기값/1,000)와 `src/game/forge.ts`의 `ForgeTable`·`buyPrice`·`hammerMs`가 같은 식이다. 사는 값 고정과 판매가 식은 2026-11-16 사용자가 고른 B안 "사는 값만 고정, 산 값을 넘는 몫에만 LUK"(`docs/balance/forge-luk.md`, SQL `20261116020000_forge_luk.sql`). 그 SQL을 실행할 때 LUK가 있는 사람은 가진 자루마다 (예전 판매가 − 새 판매가)를 한 번 받았다(`forge_luk_refunds` 표, 두 번 실행해도 한 번, 에이전트가 정함). 예전에는 사는 값·판매가 모두 × (1 + LUK/300)이었다. 단계표는 `docs/balance/tools/forge.js`의 `forge()`로 만든다(생성 스크립트는 공유 노트 폴더의 `sql-drafts/forge-steps.cjs`: `node forge-steps.cjs <forge.js 경로>`가 SQL values 줄을 낸다).
- **강화 피해 배율과 처치 골드**: 피해 × 1.03^단계는 SQL `hit_player`와 `economy.monsterDamage`, 처치 골드 round(골드 × (1 + LUK/300))는 SQL `kill_monster`와 `economy.killGold`(던전 창의 한 마리 골드, 처치 알림, 떠오르는 +G). 둘 다 사용자가 정함.
- **레벨에 필요한 경험치**: SQL `level_need`와 `src/game/level.ts`의 `levelNeed`(경험치 막대). 지금은 레벨 × 100.
- **스텟 공식**: SQL(`hit_player`, `harvest`, `buy_stat`)과 `src/game/stats.ts`의 설명. STR, DEF, AGI는 1포인트가 0.1%다(사용자가 "천천히 오래 하는 게임"이라고 정함). LUK는 1포인트에 자원 개수 평균 +0.5%(사용자 요청 2026-11-11), HP는 1포인트에 최대 체력 +1이다(0.1%면 10개를 사야 1이 올라 산 티가 안 남, 에이전트가 정함). 가격은 `stats` 표(지금 20G부터 한 번 살 때마다 +10G, 2026-11-11 사용자 요청으로 1/10). 카운터 창 위의 +1, +10, +100, +1000 버튼으로 한 번에 살 양을 고르면 아래 사기 버튼의 양과 값이 함께 바뀐다(사용자 요청 2026-11-12). 값은 1포인트씩 산 것의 합(등차수열)이라 `buy_stat(stat, amount)`와 `economy.statPrice(stat, count)`가 같은 식을 쓴다. +1을 넣은 것과 서버가 받는 최대 1000은 에이전트가 정했다.
- **작업 획득량**: SQL `harvest`의 기본 2개와 `src/game/economy.ts`의 `HARVEST_COUNT`(노동청 창의 개수와 분당 벌이). 한 번 캘 때 평균 2 × (1 + LUK × 0.005 + 도구 보너스)개다(사용자 요청 2026-11-11 "작업 획득량 2배").
- **도박장 배당과 거는 돈**: SQL `place_bet`과 `src/game/casino.ts`의 `GAMES`, `BET_MIN`(10G), `BET_MAX`(100,000G).
- **도박장 홀짝·사다리 새 모습**(2026-11-16 사용자 "홀짝게임, 사다리게임 의 ui가 너무 허접하다", 디자인 세션 `casino-ui.md`, 2026-11-16 넷째 배포): 판 배경은 `public/casino/oddeven-table.png`, `ladder-board.png`(각 320×190) 한 장씩이고, 움직이는 조각(그릇, 구슬, 금화, 덧문, 도트 글자, 강조 고리, 그림자)은 `src/ui/pixelArt.ts` 도구로 처음 쓸 때 한 번 만들어 찍는다. 사다리 판은 160 → 190(기둥 x 122·198, 위 58, 아래 146). 규칙·확률·배당·결과 문구·연출 순서와 시간은 그대로다. 걸 곳 버튼(`data-pick` 색 점, 금색 배당 딱지), 금액 칩(흰·빨강·파랑), 밝은 걸기 버튼, 결과 띠(이기면 금색, 지면 갈색)는 달팽이 경주까지 같다(`style.css` 끝 블록). 가만히 있을 때는 판을 다시 그리지 않는다(창을 만들고 그림을 읽은 뒤 한 번, 연출 중에만 매 프레임). 한 장면 0.008~0.025ms. 창은 1280×800과 휴대폰에서 화면보다 길어 창 안에서 스크롤된다(달팽이 경주도 전부터 그랬다). 휴대폰에서 금액 칸이 창보다 18px 넓던 것(`.casino-field`에 `min-width: 0`)도 고쳤다.

  - 벽 종류: 방을 나누는 흰 벽(`wall`)과 8층 뚫린 바닥 둘레 유리 난간(`glass`)은 칸 가운데를 지나는 얇은 판(`src/art/partition.ts`)이고 이웃 벽 쪽으로 팔을 뻗어 이어진다(사용자가 블록 같은 두꺼운 벽이 벽 같지 않다고 함, 2026-11-11). 엘리베이터 통과 덕트, 기둥은 매끈한 콘크리트 덩어리(`core`)다. 얇은 벽은 콘크리트나 뒤쪽 벽과는 벽이 그쪽으로 이어질 때만 붙인다(나란히 지날 때까지 붙이면 칸마다 팔이 튀어나와 톱니처럼 보임). 모두 칸을 막고 점프로 못 넘으며(`World.blocksJump`), 내 캐릭터를 가리면 반투명해진다. 미니맵에도 벽으로 보인다.
  - 7층: 엘리베이터 문은 계단실 쪽 앞면, 계단실 문 옆 짧은 벽 바로 옆이다. 가운데 홀에서 계단 앞 공간으로 바로 들어가는 문이 있고, 계단실 옆 덕트는 없다(사용자가 실제 화면에 그려 고침, 2026-11-11). 가운데 U자 계단은 계단 앞 공간에서 아래 계단, 층참, 위 계단을 걸어 올라 끝 칸(포탈)에서 8층으로 간다. 계단 앞 공간에서 위 계단 끝으로 바로 가지 못하게 난간을 뒀다. 계단실(평면도 아래 왼쪽)은 계단 무늬만 있고 어디로도 가지 않는다.
  - 8층: 엘리베이터가 서지 않아 엘리베이터 통에 문이 없다. 가운데 계단 끝 칸을 밟으면 7층 계단 앞 공간으로 내려간다. 7층 가운데 홀 위가 뚫려 있어(평면도의 X 표시) 걸을 수 없고 어둡게 그린다. 옥상으로 가는 바깥 계단 맵(`stairs`) 문은 뒤쪽 오른쪽 벽(평면도 오른쪽 변 가운데쯤, `ROOF_EXIT`)에 그린 비상구다. 사용자가 실제 화면에 자리를 표시했다(2026-11-11). 계단실은 계단 무늬만 있는 방이다.
  - 4층과 옥상: 40×40칸(`UPPER`). 7, 8층과 함께 블록과 무기를 쓰는 자유 공간이다. 1층은 20×20.
  - 층 구조를 바꾸면 그 자리에 있던 옛 블록은 서버에 남지만 벽 칸이나 바닥 밖이면 그리지 않는다(`onBlockPlaced`). 저장된 자리가 벽이면 첫 포탈 앞에서 시작한다.
  - 4층 숨은 방(`tower.ts`의 `HIDEOUT`): 바닥 오른쪽 아래 끝(x 42 변)의 한 칸(`HIDEOUT.trigger`)을 밟으면 "진우씨가 유일하게 맘 편히 쉬었던 안식처"가 크게 뜨고, 바닥 밖 빈 방(`HIDEOUT.area`, 나무 바닥과 뒤쪽 창 벽)이 서서히 나타나 걸어 들어갈 수 있다. 문구와 처음 자리는 사용자가 정했다(실제 사이트 test 계정이 서 있던 칸). 2026-11-15 사용자 요청으로 손질했다: 자리가 알려져 입구를 바닥 끝을 따라 더 아래로 옮김(거리는 에이전트가 정함), 방을 바닥 끝에서 한 칸 떼고 입구 앞 통로 한 칸(`HIDEOUT.passage`, 그림 `paintHideoutPassage`)으로만 잇게 함("그 좌표로만 진입하도록 한 칸 띄워 줘"), 방을 8×12칸으로 키우고 이불·스탠드·밥상·화분·러그를 모두 빼서 블록과 가구로 꾸미게 함("8*12로 바꾸고 사물을 뺀다", "자유롭게 꾸밀 수 있게"). 비밀 공간이라 지금 좌표는 공개 문서에 적지 않고 코드와 `art-source/secret/README.md`에만 둔다(저장소가 공개라 코드를 읽으면 알 수 있다). 4층 맵 크기는 방이 들어가게 넓힌다(`map.ts`의 `mapSize`). 통로나 방 안인지는 `tower.ts`의 `inHideout`으로 본다. 밟은 사람 화면에서만, 여는 칸·통로·방 안을 밟고 있는 동안에만 보이고(사용자 요청 2026-11-09) 벗어나면 0.5초 동안 사라지며 다시 허공이 된다. 다시 밟을 때마다 문구가 뜬다. 방 자체는 서버가 모르니 SQL이 없고, 그 안에서 접속을 끊으면 방이 열린 채로 시작한다. 여는 칸과 통로에는 블록을 놓을 수 없다(`GameMap.reserved`).
    - 방 꾸미기: 4층 설치 구역(`buildZones`)에 방을 넣었다. 방이 열려 있을 때만 바닥이라 놓을 수 있다. 방 안 블록은 서버 `blocks` 표에 평소처럼 저장되지만, 클라이언트는 `GameScene.hideoutBlocks`에 따로 두고 방이 열릴 때만 World와 화면에 올리고 닫히면 내린다(`showHideoutBlocks`, `hideHideoutBlocks`). World에 두면 방 밖 사람이 허공을 가리켜 회수하거나 위에 쌓고, 미니맵 점과 총알 막힘으로 방 자리가 드러나기 때문이다(에이전트가 정함).
    - 방 밖 사람에게 방 자리가 드러나지 않게(2026-11-15 사용자 보고 "방 안에 놓은 메모와 골드가 반짝여서 위치가 발각된다"), 내 화면에서 허공인 칸(`World.isVoid`, 닫힌 숨은 방)에 놓인 메모와 골드는 그리지 않고 줍기 안내, 골드 액수 표시, 메모 글 보기에도 잡히지 않는다(글 보기는 서버도 그 칸에 선 사람에게만 준다, `GroundItems`의 `hidden`, 방이 열리고 닫힐 때 `refresh`). 같은 까닭으로 그 칸에 선 다른 사람도 캐릭터, 이름표, 말풍선, 미니맵 점을 숨긴다(`GameScene.hideOthersInVoid`, 사람까지 숨긴 것은 에이전트가 정함). 방 안에서 쏜 총알과 작업 효과는 숨기지 않는다.
  - 계단은 높이 없이 바닥에 계단 무늬로 그렸다. 진짜 높이를 넣으려면 캐릭터, 총알, 블록의 높이 처리가 함께 바뀐다.

## 이동과 조작

- 마우스 휠(휴대폰은 두 손가락): 화면 배율을 1, 1.5, 2(기본), 2.5, 3배 중에서 바꾼다(2026-11-15 사용자 요청, `ZOOM_LEVELS`). 이름표 자리는 카메라 배율을 따라 셈하므로 따로 고칠 것이 없다.
- 방향키 또는 WASD는 화면 방향 기준이고, 두 키를 함께 누르면 마름모 변을 따라 간다. Shift는 누르는 동안 달리기, Space는 점프(블록 하나를 넘음, 두 개 이상 쌓인 칸은 못 넘음), F는 작업, I는 정보창과 인벤토리, H는 왼쪽 위 조작 안내 여닫기, Enter는 채팅.
- I 창은 정보창과 인벤토리 두 탭이다(사용자 요청 2026-11-12). 처음 열면 정보창, 그 뒤로는 마지막에 본 탭이 열린다(에이전트가 정함). 정보창(`src/ui/info.ts`)은 닉네임, 레벨, 경험치, HP, 골드, 스텟(효과 포함), 보유 자원(상점에 팔면 얼마), 보유 주식(지금 팔면 얼마, 종목별 손익)을 보인다. 예전 인벤토리 창 위의 "STR 0 · DEF 0" 줄은 정보창으로 옮겨 지웠다. 시세는 접속할 때와 거래소 창을 열 때(1분 간격) 읽는다.
- 포탈로 맵을 옮기면 누르고 있던 방향키를 잊는다. 계단 포탈에 도착하자마자 되돌아가는 일을 막으려는 것이다.
- 휴대폰(2026-11-18 사용자 "핸드폰에서 안되는 기능이 또 있는지 확인하고 수정해줘", 방법은 에이전트가 정함, `GameScene`의 `touchDown`·`touchUp`·`tap`·`updatePress`): 손가락을 떼면 차례로 본다. 메모장을 들고 내 칸 → 메모 쓰기. 작업장의 자원(그림의 불투명한 픽셀, 자원 칸이나 바로 옆 칸) → 손이 닿으면 바로 일하고 아니면 옆으로 걸어가 일한다(`workGoal`, 예전에는 F뿐이라 휴대폰에서 일을 시작하지 못했다). 손 닿는 칸(8방위 2칸)의 농장 칸 → 좌클릭처럼 심기·거두기, 블록을 들었으면 → 놓기(블록 위를 누르면 쌓기). 그 밖에는 그 칸까지 걷고, 낮은 벽 바로 너머 칸(두 칸 앞)을 눌렀는데 걸어갈 길이 없으면 넘어 뛴다. 0.45초 넘게 거의 움직이지 않고(12px 안) 누르면 손 닿는 블록을 회수한다(우클릭과 같음, 회수할 것이 없으면 뗄 때 누르기로 침). 무기를 들고 다른 플레이어(던전은 몬스터, 전쟁터 빛 밖에 숨은 사람은 뺌)를 누르면 누른 순간 공격하고 손을 뗄 때까지 연사한다. 두 손가락을 벌리거나 모으면 거리가 1.25배 바뀔 때마다 배율을 한 단계 바꾼다(휠과 같은 `stepZoom`, 0.12초 간격, 두 손가락일 때는 걷지 않음). 휴대폰(`(pointer: coarse)`, `src/ui/touch.ts`의 `TOUCH`)에만 보이는 버튼은 `src/ui/touch.css`에 있다: 아래 막대 위 오른쪽 '인벤토리'(I 대신, 왼쪽 '채팅'과 같은 줄), '채팅'과 입력줄의 '보내기'(Enter 대신, 채팅 기록을 눌러도 열림, 화면 키보드 Enter는 `key`로도 받음, 입력 중에는 인벤토리 버튼을 숨기고 채팅 칸을 화면 폭으로 넓힘), I 창 정보창의 '킬/데스 순위'(Tab 대신, 누르면 I 창을 닫고 순위를 띄우며 화면을 누르면 닫힘). 글에 든 키 이름(줍기 안내의 F, "인벤토리(I)", "I 창", "(Esc)", "(Tab: 전체)", "Ctrl+Enter", "좌클릭")은 휴대폰에서 빼거나 바꾼다(`byInput`). 달리기(Shift)와 숨은 장소 입장(이동 키를 오래 누름)은 휴대폰에 없다. 잰 값(2026-11-18 로컬, 375×812): 누르기 한 번에 자원 찾기 평균 0.02ms(최대 0.1ms, 벌목장 자원 47개), 블록·바닥 찾기 0.003~0.007ms, 상대 찾기 0.003ms, 길 찾기 약 0.8ms(예전과 같음). 매 프레임 더한 것은 누르고 있는지 보는 한 줄과 두 손가락일 때만 도는 거리 계산뿐이다.

## 전투와 성장

- 레벨은 경험치로 오른다. 한 번 캘 때 얻는 경험치는 레벨과 상관없이 작업장마다 같고(작업 1초에 1000: 채집장 1500, 채석장 2500, 벌목장 3000, 낚시터 5000), 다음 레벨에 필요한 경험치가 레벨 × 100으로 늘어 처음에는 빨리 오른다(방향은 사용자가, 숫자는 에이전트가 정함). 상대를 쓰러뜨리면 경험치 10000. 2026-11-11에 사용자가 "너무 적게 들어온다"며 모두 100배로 올렸다. 레벨은 표기만 늘고 능력치와는 무관하다. 계산은 SQL `gain_exp`가 하고, 한 번에 여러 레벨이 오를 수 있다.
- 예전에는 캘 때마다 현재 레벨에 비례해 폭발적으로 올랐다. 바꾸면서 모든 플레이어를 Lv.1로 되돌렸다(2026-11-08 사용자 결정).
