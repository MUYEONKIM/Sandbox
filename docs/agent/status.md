## 사용자가 실제 사이트에서 해 보는 중 (결과 아직 없음)

엘리베이터 변경의 테스트 항목: 엘리베이터 안 포탈이 "→ 층 버튼" 하나뿐인지, 버튼판 창의 "○층에서 내리기"로 탔던 층에 나가는지, 1·4·7층 이동과 임대 층 안내가 되는지.

작업장 변경의 테스트 항목: 각 작업장 도착 귀퉁이에 장식 벽이 보이는지, 블록을 놓고 새로고침해도 남는지(사라지면 SQL 문제), 장식 벽은 우클릭으로 회수되지 않고 옆 블록과 이어져 보이는지, 작업장에서 PK 피해가 들어가는지, 시작마을은 여전히 총과 블록이 막혔는지.

`2ef6cd7`과 `ffad504`의 테스트 항목:

1. 4·7·8층과 옥상이 넓은지, 넓어진 바닥 가장자리에 놓은 블록이 새로고침 뒤에도 남는지(남지 않으면 블록 정책 SQL이 안 들어간 것)
2. 엘리베이터 버튼이 7→1 세로 한 줄인지, 2·3·5·6층은 "임대 줬습니다"가 뜨는지
3. 엘리베이터 포탈을 타면 엘리베이터 안으로 들어가는지, 버튼판에 탔던 층 불이 켜지는지, 고른 층에 내리는지, "내리기"로 탔던 층에 돌아가는지
4. 7층 사무실 안 난간 계단으로 8층에 가고 같은 자리 계단으로 내려오는지, 위 방향키를 계속 눌러도 8층 도착 칸에서 멈추는지
5. 8층 "→ 바깥 계단"으로 나가 위 방향키로 옥상까지 가는지, 옥상에서 내려와 8층으로 돌아가는지, 바깥 계단의 미니맵이 좁은 띠 모양인지
6. 휴대폰에서 바닥을 누르면 그 칸까지 걷는지, 멀리 있는 포탈을 누르면 가서 타는지, 총을 들고 다른 플레이어를 누르면 공격하는지(바닥을 누를 때는 총이 나가지 않는지)
7. PC의 마우스 클릭이 예전처럼 공격과 블록 설치인지, 이미 7층에 있던 계정이 그 자리에서 시작하는지

- 확인함: `rooms` 표와 `give_room` 함수가 없어짐(`20261107040000_tower.sql`), `top_players`, `tools` 있음.
- 확인 못 함: 블록 insert 정책(`20261107050000`), `hit_player` 본문(1층 공격 금지), 스텟 0.1% 공식(`20261107020000`). 사용자의 블록과 전투 테스트로 확인한다.

`ffad504` 이후의 변경은 SQL이 필요 없었다.

## 사용자가 아직 정하지 않은 것

- 스텟 가격(기본 200G, 1포인트마다 +100G). 10포인트 6,500G(약 36분 노동), 100포인트 515,000G(약 48시간)라고 알렸다.
- 휴대폰에서 아직 안 되는 조작(블록, 점프, 달리기, 작업, 인벤토리, 채팅)을 어떻게 할지. 휴대폰 화면에서는 키 안내, 미니맵, 랭킹 패널이 위쪽 절반을 가린다.
- 계단을 진짜 높이로 바꿀지(지금은 평면에 계단 무늬).
- 엘리베이터 안에서 공격을 막을지(지금은 쓸 수 있고, 막으려면 SQL `hit_player`도 바꿔야 함).
- 9층, 2·3·5·6층의 쓰임(지금은 못 감).
- 개인 방과 가구: 사용자가 행복 아파트를 철거하면서 개인 방을 없앴다. 나중에 다시 만들면 가구 한 개를 한 줄로 저장해 약 115바이트였던 측정치를 참고한다.
